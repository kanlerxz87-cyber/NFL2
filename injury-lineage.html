Every Week 10 injury file in this repository, the official read it came from, what it reconciles against, and the change between reads. Counts and differences only; nothing is inferred. No file here is a retained raw capture, so none is verified byte-for-byte (see FL-90 on the Flagged for Review page).

What this page establishes, and what it does not

  • Established: how many player rows each file holds, how many clubs it covers, how each file compares with the earlier file it refreshes, and whether the 254-row headline was correct (FL-87: it was not).
  • Established for four clubs: the 44 player rows for WAS, NYG, NE and DET on the official page, read on 15 November, match both the four-club 15 November file and the full 15 November read on all 44 rows. They match the 13 November file on 31 of 44. The 13 differences are the NE and DET rows already flagged in FL-73 and FL-74.
  • Not established: which of the 17 added players and 51 changed values reflect the league's own changes and which reflect transcription. No retained capture exists to separate them (FL-88).
  • Not established: the 12 November transcripts disagree on 12 values for the same players (FL-89).

    How these tables are produced

    Computed by scripts/injury_lineage_d8372691.py, which reads only repository files and writes the four CSVs behind this page. The eighth read (the full 15 November hub, 347 rows) was transcribed by session 8dee7df7; it is registered as S-INJ-8DEE and is reconciled here, not re-transcribed. Run with --check, it fails if any output differs from its inputs, and CI runs that check on every push. The live transcription is data/injury_live_chunk_d8372691.csv. The Kansas City block was cut off in the page text and is not used. The official page remains the reference for every value: nfl.com/injuries.
