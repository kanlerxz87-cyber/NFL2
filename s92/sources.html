How verification was performed

  1. The official page was retrieved through the session's page-fetch path and its content stored verbatim

under s92/raw/ for each injury chunk, and transcribed into a pipe-delimited table for standings, schedule, depth charts and rule changes.

  1. The repository file was parsed with the same field vocabulary and compared row by row, keyed on club

and player slug (injury), or club abbreviation (standings, schedule).

  1. Arithmetic identities were re-derived rather than trusted: points-for equals points-against; wins plus

losses plus ties times two equals twice the game count; net points equals points for minus points against.

  1. Where a page could not be re-read (game scores render client-side), the row says so instead of

claiming a verification that did not happen.

A limitation of this session, stated plainly

Bash-level HTTPS to the league's hosts fails with a TLS error from this sandbox. Every official page here was therefore retrieved through the session's page-fetch path, which returns rendered text. That is sufficient for tables and prose, and not sufficient for client-rendered score boxes — which is why the audit carries a NOT-RE-VERIFIABLE row for game scores rather than a green tick.
