The missing-information register

This is the discovery plan the brief asked for: the information that does not exist yet, where it would come from, and what would have to happen for it to arrive. It is organised by what is missing, not by what we would like to build, so that the roadmap's inputs are visible before the roadmap.

How each gap closes

  • Q-101 Price feed — Contract a licensed feed; store point-in-time prices; replay one season before any strategy runs
  • Q-102 Settlement — Adopt one venue's published rulebook as the settlement spec and record its version
  • Q-103 Player-level data — License one provider; version the extract; never mix providers mid-season
  • Q-104 Depth authority — Use club charts as a prior, then replace with realised snap share once participation data is licensed
  • Q-105 Filing cadence — Scrape the hub on a fixed schedule and store every filing, not the latest
  • Q-106 Game status semantics — Encode three states (out / designated / not-yet-filed) and never collapse them
  • Q-107 Home-field and travel — Pool several seasons; publish the interval; treat neutral sites as zero
  • Q-108 Sample size — Pre-register, then require the gate to be met before any leaderboard entry is marked skilled
  • Q-109 Correlation inputs — License play-by-play; compute pairwise phi on the same game keys
  • Q-110 Reward design — Owner decision; then encode as a gate that a strategy cannot pass by self-report
  • Q-111 Luck definition — Fix the filter set and thresholds in advance; any change requires a new version
  • Q-112 Ownership of truth — Publish a metric ownership table; other trees link instead of restating
  • Q-113 Model validation — Score against realised outcomes now; add closing-line value later
  • Q-114 Injury data licence — Record a fair-use note per source, as the existing sources register does
  • Q-115 Prop markets — Pick two markets, write their settlement rules from the venue rulebook, then model

The trap this register is designed to avoid

It is easy to spend a season building models on data that already exists and calling the result skill. The register exists so that the missing inputs are named before the models, and so that a strategy that depends on an input we do not have is visibly blocked rather than quietly over-fitted. The strategy registry applies exactly this rule: eight of ten entries are blocked on a named missing input, and the two that are not blocked are labelled research, not skill.

What cannot be discovered from inside this session

Three items need a decision or a purchase, not a search: the price licence (Q-101), the participation licence (Q-103) and the reward budget (Q-110). They are recorded here so they are not mistaken for research tasks that a later session could finish on its own.
