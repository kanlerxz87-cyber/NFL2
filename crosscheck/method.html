How this was verified

The rules this build follows, the tools it refuses to use, and the one test anyone can run to falsify its numbers.

The rules

  1. Only a league page counts as a source. A row may cite nfl.com, operations.nfl.com or static.www.nfl.com. A club site is evidence, and is labelled as such. A sibling tree in this repository is an input, never a source.
  2. A blank is a value. Where the league published nothing, the cell renders as not published. It is never zero and never an estimate.
  3. Prose counts are measured. Every number in a sentence is computed from the file it describes at build time. If the prose and the file disagree after an edit, the build is what changes.
  4. Nothing is inferred across a gap. If a player row is absent, the player is unreported, not healthy. Seattle's missing block is the case that proves why.
  5. Unverifiable stays flagged. It does not get dropped quietly; it goes on the Flagged for review page with the reason it could not be closed.

How the injury re-check actually worked

The live table was transcribed club by club into crosscheck/data/live_wk10_injuries_2026-11-12.csv — every player, position, injury note, participation string and game status, exactly as printed. The published file and the live transcript were then joined on the pair (club, player) and compared field by field. No fuzzy matching, no name normalisation beyond the league's own spelling. The result is reproducible by opening the same page and counting.

That join is why the difference report can name players rather than report a total. It is also why the 25 added rows are a list, not an inference: each is a player the live page prints and the published file does not.

The one test that falsifies this build

Take data/games_2026_wk1_9.csv out of the repository root, compute a Pearson correlation between home and away points, and compare it to the number on the lineage page. If they differ, this build is wrong. All 6 published coefficients were recomputed this way and 6 matched to six decimal places.

What this build did not do

  • It did not re-open all 136 game pages individually. It re-opened 13 and relied on the repository's own arithmetic reconciliation for the rest. That is stated on the page rather than glossed.
  • It did not attempt to reach a price feed. None is reachable from this environment, and none is licensed.
  • It did not modify any file owned by another session. The claim and the scope are recorded in COORDINATION.md.
